## 3. 의존성 누락 수정 (`email-validator`)

### 문제
서버 재시작 시 다음 오류 발생:
```
ImportError: email-validator is not installed, run `pip install 'pydantic[email]'`
```
`backend/app/routers/senders.py`에서 Pydantic의 `EmailStr` 타입을 사용하는데, `email-validator` 패키지가 설치되어 있지 않았음.

### 수정
- `pyproject.toml` — `"pydantic>=2.0"` → `"pydantic[email]>=2.0"`
- `uv pip install "pydantic[email]"` 실행 → `email-validator==2.3.0`, `dnspython==2.8.0` 설치

## 4. 동기화 중복 실행 및 카테고리 비정상 증가 수정

### 문제
페이지 새로고침 시마다 Categories 숫자가 증가하는 현상. 기존에 처리된 기사 내용이 재반영되는 것으로 보임.

### 원인 분석

| 원인 | 상세 |
|------|------|
| `misfire_grace_time=None` | APScheduler 재시작 시 당일 7AM 스케줄을 "아직 유효한 misfire"로 간주해 즉시 실행. 서버 재시작마다 `run_ai_processing()` 호출 → 미처리 기사 카테고리 변경 |
| 동시 실행 방지 부재 | 스케줄 sync + 수동 sync 버튼 + 초기 sync 스레드가 동시에 실행될 수 있는 구조 |
| 재시작 후 미처리 기사 방치 | 서버 재시작으로 AI 처리가 중단된 경우, 다음 수동 sync 전까지 미처리 기사가 방치됨 |

### 수정 내용

**`backend/app/sync_state.py` (신규)**
```python
import threading
sync_lock = threading.Lock()
```
순환 import 없이 `main.py`와 `routers/sync.py`가 동일한 lock을 공유하기 위한 전용 모듈.

**`backend/app/main.py`**
- `misfire_grace_time=None` → `misfire_grace_time=3600` (1시간 이내 misfire만 허용)
- `_scheduled_sync`, `_initial_sync` — `sync_lock.acquire(blocking=False)` 추가로 동시 실행 방지
- `_resume_ai_processing()` 함수 추가 — AI 처리만 단독 재개
- `lifespan` 시작 시:
  - DB 비어있음 → `_initial_sync` (기존)
  - 미처리 기사 있음 → `_resume_ai_processing` 자동 실행 (신규) — 재시작 후 중단된 AI 처리 자동 재개

**`backend/app/routers/sync.py`**
- `sync_lock` 적용: 이미 동기화 중일 때 수동 Sync 요청 시 HTTP 409 반환
- `finally: sync_lock.release()` 보장으로 예외 발생 시에도 lock 해제

### 동작 변화 요약

| 상황 | 수정 전 | 수정 후 |
|------|---------|---------|
| 서버 재시작 (7AM 이후) | 스케줄러 즉시 sync 실행 | 1시간 이내 misfire만 실행 |
| 미처리 기사 잔존 시 재시작 | 다음 수동 sync까지 방치 | 재시작 시 자동 AI 처리 재개 |
| 동시 sync 요청 | 중복 실행 | 409 응답 반환 |
| 예외 발생 시 | lock 미해제 가능 | `finally`로 항상 해제 |
